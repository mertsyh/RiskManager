Final submission guide

Follow the four stages below to collect, lay out, package and submit your complete project. Everything you need to include and every responsible person is named here.

🛈 Hover dotted terms for help 🖱️ Right-click any stage or file for options 📋 Templates are copy-ready

Who uploads — read this first

1st

Coordinator

If your team has a coordinator, the coordinator uploads the package.

2nd

Team leader

No coordinator? The team leader uploads it.

3rd

Any one member

Only if neither is available, any single team member may upload.

✅ One package per team. Once the responsible person has uploaded it, no other member needs to submit anything.

3 Package & verify Coordinator / leader

3Prove it builds, then archiveCoordinator / leader
  • Rebuild from your files alone. On a clean copy of the folder, follow your own DEPLOY.md step by step. If it fails, fix the directives or add the missing file.
  • Run it. Open the result and play through it once.
  • Archive. Compress the whole folder into a single .zip named with your team id.
  • Check the GitHub link. Open the URL in REPOSITORY.txt in a private window — public, and matching your packaged source.
Definition of done: a grader, using only your archive, can read your directives, build the game in the stated environment, run it, and open your proposal data.

4 Submit Coordinator → leader → any member

4Upload one package — the responsible person onlySee “Who uploads”

  • Confirm the upload completed and the file size looks right.
  • Tell your team it is done — no one else uploads.
